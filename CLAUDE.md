# ClipLite

Легкий менеджер буфера обміну для Windows у стилі **ClipMate**. WinForms, .NET Framework 4.x, один exe, темна тема.

Спілкуйся з користувачем **українською**. UI програми двомовний (українська / англійська).

## ⚠️ Правила, порушення яких уже ламало програму

1. **Ніколи не перезбирай `bin\ClipLite.exe`, поки ClipLite запущений.** Перед збіркою перевір `Get-Process ClipLite`; якщо програма працює — збирай у тимчасову папку або попроси користувача вийти через трей. `build.cmd` сам відмовляється збирати, коли ClipLite запущений.

   Раніше проєкт лежав на Google Drive, і його віртуальний диск (на відміну від NTFS) дозволяв перезаписати запущений exe. Процес потім брав ще не викликані методи з нового файлу й падав з `BadImageFormatException: Bad IL range`: одного разу так зламався пункт трею «Вихід», і програму неможливо було закрити. Зараз проєкт на звичайному диску (`C:\ClipLite`), де Windows блокує запущений exe, тож збірка просто впаде з «file in use» — не страшно, але однаково перевіряй процес, щоб не гадати над помилкою компілятора. Якщо проєкт колись повернеться на хмарний чи мережевий диск, правило знову стає критичним.
2. **Поводься як ClipMate.** Користувач порівнює ClipLite саме з ClipMate. Кожне копіювання, зокрема з вбудованого редактора, має з'являтися в історії. Вибраний у списку кліп одразу йде в буфер обміну. Коли вибір неоднозначний, роби як у ClipMate і не прибирай видимий відгук (новий рядок у списку, звук) заради «чистоти».

## Збірка

```bat
build.cmd
```

- Компілятор — `%WINDIR%\Microsoft.NET\Framework64\v4.0.30319\csc.exe`, **лише C# 5**: без `$"..."`, `?.`, `nameof`, `=>`-членів та ініціалізаторів автовластивостей.
- `/codepage:65001`: файли у UTF-8 без BOM, кирилиця в коді дозволена.
- Звуки з `assets\sounds\*.wav` вбудовуються як ресурси `ClipLite.Sounds.<Name>.wav`. Формат — 16-bit PCM mono 44.1 kHz, бо `SoundPlayer` не грає float WAV.
- Із Git Bash `csc` викликати незручно: MSYS ламає аргументи `/opt`. Користуйся PowerShell.

## Структура `src`

| Файл | Що всередині |
|---|---|
| `Program.cs` | один екземпляр (mutex), `--tray`, portable-режим, `crash.log` |
| `MainForm.cs` | захоплення буфера, список, редактор, вставка, розмітка |
| `MainForm.UI.cs` | побудова інтерфейсу, малювання рядків списку |
| `MainForm.Events.cs` | меню, клавіші, drag&drop, копіювання в редакторі |
| `ClipStore.cs` | зберігання кліпів (`.clp`), колекції InBox / Safe / Trash, ліміти |
| `ClipboardIO.cs` | читання/запис буфера, виключення паролів, `PasteInto` |
| `ListHeader.cs` | заголовок стовпців Назва/Дата з сортуванням |
| `OptionsDialog.cs` | вікно параметрів (мова, автозапуск, гаряча клавіша, звуки…) |
| `Loc.cs` | локалізація; `TextCase.cs` — зміна регістру; `Sounds.cs` — звуки подій |
| `Theme.cs` | кольори та іконки, намальовані кодом; багаторозмірні ICO для трею |

## Важливі рішення в коді

- **Локалізація:** ключем є англійський текст — `Loc.T("Paste")`. Довговічний UI реєструє тексти через `Loc.Bind(() => item.Text = Loc.T(...))`, щоб мова перемикалася без перезапуску. Нові рядки додавай у словник `uk` у `Loc.cs`.
- **`store.Lists[...]` завжди впорядковані від нових до старих.** На це спирається `EnforceLimits`, який витісняє останній елемент. Сортування за стовпцями працює з **копією** (`ViewItems()`), списки на місці не сортуй.
- **Safe (укр. «Збережені») ніколи не обрізається лімітом.** Дублікати шукаються лише у InBox.
- **Власні записи в буфер не захоплюються:** `ownSeq` / `ignoreUntil`, а також перевірка `pendingPid == myPid`. Копії з редактора додаються в історію явно через `AddToHistory`, при цьому вибір і вміст редактора не змінюються (`RefreshList(false)`).
- **Вибір кліпа кладе його в буфер** (`LoadSelectionToClipboard`) лише за дією користувача: клік мишею чи стрілки, із затримкою 150 мс. Видалення/переміщення кліпа теж дія користувача: кліп, що отримав вибір, іде в буфер (`SelectIndexAfterRemoval`). Інші програмні зміни вибору буфер не чіпають. Якщо кліп уже в буфері, його не перезаписуємо, бо зберігаємо лише Text/HTML/RTF/PNG/Files і втратили б решту форматів.
- **Невдалий запис у буфер ніколи не мовчить:** «Вставити» не тисне Ctrl+V, а «Вирізати» не видаляє текст.

## Дані користувача

`%APPDATA%\ClipLite\` містить `settings.ini`, `crash.log` і `clips\{InBox,Safe,Trash}\NNNNNNNNNN.clp`. Дані **не шифруються** й **не синхронізуються** між комп'ютерами. Не виводь вміст кліпів у відповідях: для діагностики читай лише заголовки (номер, час, джерело, формати, розміри).

## Тестування

- Тестові програми (harness) пиши в тимчасовій папці й компілюй разом із `src\*.cs` без `Program.cs`, використовуючи `/main:<Клас>`. Вікна запускай через `Start-Process -Wait`, бо PowerShell не чекає GUI-процес.
- Якщо тест пише в **справжній** буфер, поки в користувача працює ClipLite, додавай формат `"Clipboard Viewer Ignore"`, щоб не засмітити історію. Буфер після тесту відновлюй.
